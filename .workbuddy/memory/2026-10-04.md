### 9.9 ★ 更正：push 凭据卡住的真实原因（不是「GCM 拒交」）
- 现象：`git push` 前台超时转后台后挂 4 分钟，最终报
  `fatal: could not read Username for 'https://github.com': terminal prompts disabled`。
- **误判**：先前记为「GCM 不交存储凭据」。**实际 GCM 是有凭据的**——
  `printf 'protocol=https\nhost=github.com\n\n' | git-credential-manager get` 正常返回 username+password。
- **真因**：WorkBuddy 自带的 PortableGit 全局配置
  (`.../PortableGit/versions/1.2.0/etc/gitconfig`) 把
  `credential.helper` 设成了 **`helper-selector`**（沙箱 shim，读不到真实存储）。
  于是 git 拿不到用户名，`GIT_TERMINAL_PROMPT=0` 又禁了交互 → 直接 fatal。
- **解法（最终有效）**：**先清空 helper 列表再只留 manager** ——
  ```bash
  GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=false \
    git -c credential.helper= -c credential.helper=manager push origin main
  ```
  单独 `-c credential.helper=manager` **无效**（`-c` 是追加，shim 仍在首位挡住并挂住）。
  先跑 `printf 'protocol=https\nhost=github.com\n\n' | ... credential fill` 探针确认秒回再推。
- ✅ **结果**：`7c9f509..395a354 main -> main` 推送成功，`git rev-list --left-right --count main...origin/main = 0	0`。
- 另注：**两个 push 并发会互相抢锁/堆积**（本次见 2 组 git-remote-https + 2 个 credential-helper 进程），
  超时转后台后不要立刻再发一条 push，先 `git rev-list --left-right --count main...origin/main` 看状态。
- 该坑已补进 user skill `git-remote-align` 第 2.1 节。
