## 关键设计决策
1. **学号不入画像**：`SENSITIVE_FIELDS={student_id,id_card,phone,email}` 只报字段名。
   理由：挂到 UserProfile 上就会被 `build_context` 拼进 prompt → 随云端重写外发。
   宁可少填一个字段，也不让强标识进入可能外发的上下文。
2. **入库存原文，云端前才粗化**：`mask_for_cloud()` 是唯一外发闸口。
   计科2301 → `grade_hint=大三`；计算机科学与技术 → `education_field=理工科`；
   映射表外一律丢弃不猜测。正确表述 = 「本地存储 + 外发前脱敏」，**不是「绝不外发」**。
3. **不做模糊匹配绑定**：宁可少填，绝不把「韩佳文」塞进 `birthday_person`（寿星）。
4. **确认护栏**：`apply_extracted_profile(confirmed=False)` 只回显不落盘。
5. **空画像零影响**：`_stage_boost` 在 learning_stage 为空时返回 (0.0,"")，
   实测空画像与 `brain=None` 两路 priority 逐行一致。

## ★★ 中文正则实测踩坑（写了 5 轮才对，值得单独记）
首版 7/19 字段级准确率 → 中途退到 5/17 → 最终 18/18。三个反直觉点：
1. **惰性量化 + 尾部锚定在中文上不可靠**：`{2,10}?(?:大学|学院)` 惰性只吞最短就要求后缀，
   「哈尔滨工业大学」被切坏，且「工业大学」是「大学」的分支，引擎向左优先试短后缀成功即停。
   正解：**贪婪吞 + 尾部锚定 + handler 里剥离噪声前缀**。
2. **双向语序都要覆盖**：「专业是软件工程」（cue 后）与「计算机科学与技术专业」（cue 前）
   中文里都常见，首版只写前者，后者 3 条用例全挂。
3. **白名单不能只看末字**：「计科2301」末字是「科」，取 `cn[-1]` 判断必然漏抽。
4. **负向前瞻只挡 1 个字符**：`(?<![学号…])` 挡不住「我是计科2301」的「是」。
5. **否定窗太窄**：「我叫你不要写」里「不要」距 cue 仅 5 字，8 字窗口虽覆盖但被字段顺序绕过。
   最终改成**先做否定门禁再抽任何字段**。

★ **方法论：正则/解析类代码「看着对」几乎必然错**。首版全部正则我都自认为正确，
跑一次测试 8/18 挂。中间还有一次修完反而退步（5/17）。每轮都要打印逐字段实际值+诊断，
