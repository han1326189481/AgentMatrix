## 本轮实际改动（commit `edad552`，9 文件 +378/-27）

### Bug 1：CapabilityGraph PATCH 无效写入（真 bug，修了）
`api/v1/brain/router.py:109` 每次请求 `PersonalBrain(user_id=...)` 新建实例
→ `self.capability` 是全新空对象 → `update()` 后随请求丢弃；
且 `_save_profile()` 只序列化 `UserProfile`，不含 capability。
现象：`GET /api/v1/brain/{uid}/capability` **永远 total=0**。

修法（关键设计决策）：
- 能力图谱与画像**共用同一 JSON 的 `capability` 子键**，不另开文件
  → 复用 `_profile_path` ⇒ conftest 既有的 `_isolate_personal_brain_profiles`
  自动覆盖，**不需要为能力图谱新增 fixture**，也就不存在「新路径忘记隔离」的漏网口
- `__init__` 里 `_load_capability()`；PATCH 后显式 `brain.save()`
- `_save_capability()` 只改 `capability` 一个字段，不整体重写 profile，避免并发写旧值
- 原子写 + `.bak`

### Bug 2：IntentGraph 零持久化
`service.py:115` 每次请求 `IntentGraph(user_id="default")` → 重启即清零
→ `get_consecutive_domain_run()` 软节流信号在真实使用中**几乎恒为 0**。
修法：`storage/intents/{user_id}.json`，`record()` 即持久化，
`storage_dir` 可注入 + `persist=False` 开关，单条损坏记录跳过而非整图报废。

### Bug 3（★本轮最大收获）：pytest 跑完不退出 —— 10-09 误诊的那个
**症状**：34 项全 PASSED 但进程不退出。10-09 记录「test_phase4 单独跑超 150s
被 SIGTERM」，当时**误诊为「卡在加载 916KB 图谱」**。

**实测推翻了这个猜测**：`get_skill_graph()` 加载只要 **0.74s**。

真根因（faulthandler dump 线程栈抓到）：
```
_pytest/pathlib.py:167 rm_rf
  → sitecustomize.py:909 _try_trash_via_binary     ← WorkBuddy 安全删除护栏
     [SAFE_DELETE_FAIL_CLOSED] trash-failed
       [Errno 53] 找不到网络路径 '\\?\C:\...\pytest-of-13261\garbage-...'
  → subprocess.run 卡在 join → 管道读端不关 → 永久阻塞
```
pytest 收尾删 `%TEMP%\pytest-of-*` → 撞上护栏 → 长路径前缀 `\\?\` 处理不了
→ fail-closed → 死锁。**在错的原因上猜了两次，这次靠 dump 栈才拿到证据。**

修法：`backend/pyproject.toml` addopts 固化 `--basetemp=.pytest_tmp`
（+ `.gitignore` 加 `.pytest_tmp/`）。
效果：test_phase4 从「跑超 150s 被杀」→ **34 passed in 2.00s 正常退出**。
⚠️ `CODEBUDDY_SAFE_DELETE_ENABLED=0` **单独设没用** —— 护栏在 `sitecustomize.py`
第 35 行模块导入时读一次并缓存进 `_SAFE_DELETE_ENABLED` 常量。

## 工具坑（新增）
- `pytest --timeout=30` 未装 pytest-timeout，会报 unrecognized arguments
- `tail -25` 会把 pytest 输出全缓冲住 → 看不到进度，误判成「卡住」。
  跑测试直接 `> logfile 2>&1` 落盘再看
- PowerShell 输出常是 UTF-16，Read 报「binary file」→ 先
  `Get-Content -Encoding UTF8 | Out-File xxx.txt -Encoding utf8` 转一道
- PowerShell 里调 `python -c` 双引号嵌套会被 bash/PowerShell 混合解析搞坏 →
  写临时 .py 文件跑
- `graph_health.py` 是 bash 脚本，用 PowerShell tool 直接跑会输出二进制乱码
