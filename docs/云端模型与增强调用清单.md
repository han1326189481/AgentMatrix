> 定版日期：2026-09-22
> 定版人：佳文
> 结论：**项目内所有云端调用（云端增强 / 云兜底 / 云端视觉 / 自学习概念判定）统一走 `DeepSeek-V4.1-Flash`；
> 其 API 模型 id 是 `deepseek-flash`；`deepseek-v4-pro` 已弃用，不得再出现在任何新增代码里。**

> ⚠️ **2026-10-04 命名修正（重要）**：本文档早期版本把**网关显示名** `deepseek-flash`
> 当作 model id 记录，这是错的 —— 网关只认 id `deepseek-flash`，传显示名会被 400 拒。
> 本文已统一改为 `deepseek-flash`；正文下方历史段落中出现的旧写法则同属该修正范围。
> 判定方法：**填进 `.env` / `app_config.json` 的必须是 id**，显示名只用于界面展示。

## 一、定版规则（新增代码必须遵守）

1. **不得硬编码模型名。** 任何云端调用必须通过下列封装函数，模型名从 `settings.deepseek_model`（文本）或 `settings.deepseek_vision_model`（视觉）读取。
2. **文本与视觉同源。** 二者当前都指向 `deepseek-flash`，但语义上分开配置——将来若要拆分只需改 `.env`，不必动代码。
3. **改模型要同时改两处**（见第二节"双真相源"），只改 `.env` 会出现"配置写了但实际没走"的情况。
4. `deepseek-v4-pro`、`deepseek-v4-flash` 为**历史值**，仅在注释与本文档中作为弃用记录出现。
5. **视觉本地优先**：常规识图一律走本地 `qwen2.5vl:7b`，**不调云端 API**。「云端视觉」只服务少数显式场景（见 C 层），绝不做成每次识别的默认动作。

## 二、模型名从哪里读（真相源链）

```
.env  DEEPSEEK_MODEL / DEEPSEEK_VISION_MODEL
  └─> app/config.py  settings.deepseek_model / deepseek_vision_model     （默认值已改为 v4.1-flash）
        ├─> core/llm/client.py            LLMClient.deepseek_model / deepseek_vision_model
        ├─> core/model_registry.py        ModelRegistry._cloud_model / _cloud_vision_model
        │     └─> agents/base/agent.py    BaseAgent.cloud_model            （ResultAgent 等由此取模型名）
        └─> core/llm/web_search_plugin.py WebSearchPlugin.deepseek_model
        └─> core/llm/encyclopedia.py      fetch_authoritative_definition() 的兜底模型
```

**双真相源（易踩坑）：** `LLMClient.generate_cloud()` 在运行时**优先读** `config/app_config.json` 里的云端模型条目，匹配不到才回退 `settings.deepseek_model`。因此改云端模型必须两处同步：

| 位置 | 作用 | 当前值 |
|---|---|---|
| `backend/.env` → `DEEPSEEK_MODEL` | settings 默认来源 | `deepseek-flash` |
| `backend/config/app_config.json` → `models[]` 中 provider=deepseek 的条目 | 运行时优先读取 | `deepseek-flash` |

开发环境 `get_data_dir()` 返回 `backend/`，所以读的就是上面这份 JSON；打包环境读 `%APPDATA%/AgentMatrix/config/app_config.json`。

## 四、本次修复的真实缺陷

**`generate_cloud()` 云端增强被静默降级为本地推理。**

- 原逻辑：未指定模型 / 未匹配到时取 `user_models[0]`。
- 而 `config/app_config.json` 的 `models[0]` 是 **`qwen2.5vl:7b`（provider=ollama）**。
- 后果：`generate_by_config()` 见 `provider == "ollama"` 直接转 `generate_local()` —— 调用方以为走了云端增强，实际跑的是本地 7B。
- 修复：`generate_cloud()` 现在先过滤掉 `provider in ("", "ollama")` 的条目，只从真正的云端模型里选。
- 验证：云端候选 `['deepseek-flash']`，不再包含 ollama 条目。
