## 二、EXE 打包方案

### 2.1 方案对比

| 维度 | Tauri v2 | Electron |
|------|----------|----------|
| 打包体积 | 5-15 MB | 150-200 MB |
| 启动速度 | <1秒 | 2-5秒 |
| 内存占用 | ~50MB | ~150MB |
| 技术栈要求 | Rust + Node.js | Node.js |
| Windows 支持 | Win10+ (需 WebView2) | Win7+ |
| 自动更新 | 内置 | 需 electron-updater |
| 本团队学习曲线 | 高（Rust 全新） | 低（JS 熟悉） |

**结论：Tauri v2**。体积和启动速度优势值得承担 Rust 学习成本。

### 2.2 Tauri 通信架构

```
┌─────────────────────────────────────────────────────┐
│                    Tauri 进程                        │
│  ┌───────────────────────────────────────────────┐  │
│  │              WebView (WebView2)                │  │
│  │  ┌─────────────────────────────────────────┐  │  │
│  │  │  Next.js 静态导出 (file:// 协议)         │  │  │
│  │  │  ├── Axios → http://127.0.0.1:8000      │  │  │
│  │  │  └── Socket.io → ws://127.0.0.1:8000    │  │  │
│  │  │       (降级: HTTP polling)              │  │  │
│  │  └─────────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────────┘  │
│                         │                            │
│  ┌──────────────────────┴────────────────────────┐  │
│  │           Rust 后端 (Tauri Core)               │  │
│  │  ├── sidecar 管理: 启动/监控/重启              │  │
│  │  ├── 窗口管理: 大小/位置/托盘                  │  │
│  │  └── 自动更新: 检查/下载/安装                  │  │
│  └──────────────────────┬────────────────────────┘  │
│                         │ spawn                      │
│  ┌──────────────────────┴────────────────────────┐  │
│  │       Python 后端 (PyInstaller EXE)            │  │
│  │  FastAPI → uvicorn → 127.0.0.1:8000           │  │
│  │  ├── 只读资源: sys._MEIPASS (configs, prompts) │  │
│  │  ├── 可变数据: %APPDATA%/AgentMatrix/          │  │
│  │  │   ├── logs/        (日志)                   │  │
│  │  │   ├── cache/       (知识库缓存)             │  │
│  │  │   └── config.json  (用户配置)               │  │
│  │  ├── Ollama (localhost:11434)                  │  │
│  │  └── DeepSeek API (api.deepseek.com)           │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**通信方式**：前端 WebView 直连 `127.0.0.1:8000`（HTTP + WS），不经过 Tauri IPC 代理。理由：复用现有 Axios/Socket.io 代码，零改动。

**CSP 配置** (`tauri.conf.json`)：

```json
{
  "app": {
    "security": {
      "csp": "default-src 'self'; connect-src http://127.0.0.1:8000 ws://127.0.0.1:8000; style-src 'unsafe-inline' 'self'; script-src 'self' 'unsafe-eval'; img-src 'self' data: https:"
    }
  }
}
```

**Sidecar 崩溃恢复策略**：

| 参数 | 值 | 说明 |
|------|-----|------|
| 初始重试间隔 | 1 秒 | 首次崩溃后等 1 秒 |
| 退避倍增 | ×2 | 每次重试间隔翻倍 |
| 最大间隔 | 10 秒 | 退避上限 |
| 时间窗口 | 1 分钟 | 滑动窗口计数 |
| 窗口内最大重试 | 5 次 | 超出后进入"永久故障" |
| 永久故障处理 | 停止重试，前端显示 ErrorOverlay + "手动重启后端"按钮 | 不清除后端已有数据 |

**Sidecar 配置** (`tauri.conf.json`)：

```json
{
  "bundle": {
    "externalBin": ["backend/agentmatrix-backend.exe"]
  },
  "windows": {
    "hide": true
  }
}
```

`"windows": { "hide": true }` 确保 Python 子进程不弹出命令行窗口。同时后端 Python 自身不执行 `print()` 输出到 stdout，仅写日志文件。

**手动重启后端实现**：前端 ErrorOverlay 的"手动重启后端"按钮通过 Tauri IPC 调用 Rust 命令触发重启：

```rust
// Rust 端 (src-tauri/src/main.rs)
#[tauri::command]
fn restart_sidecar(state: tauri::State<AppState>) -> Result<(), String> {
    // 1. 杀死当前 sidecar 进程（如果还存活）
    // 2. 重置崩溃计数器
    // 3. 重新 spawn sidecar
    // 4. 等待端口就绪
}
```

```typescript
// 前端 (ErrorOverlay.tsx)
import { invoke } from '@tauri-apps/api/core';
await invoke('restart_sidecar');
```

> **注意**：前端是静态 JS，无权限操作本机进程。必须通过 Tauri `invoke` API 桥接到 Rust 层执行。不可在前端直接调用 `ChildProcess.spawn`。

### 2.3 PyInstaller 打包细节

**目录分类**：

| 数据类型 | 路径 | 权限 |
|----------|------|------|
| 可执行文件 | `sys._MEIPASS` (PyInstaller 临时目录) | 只读 |
| 配置文件 (`configs/`, `prompts/`) | `sys._MEIPASS` | 只读 |
| 日志文件 | `%APPDATA%/AgentMatrix/logs/` | 读写 |
| 知识库缓存 | `%APPDATA%/AgentMatrix/cache/` | 读写 |
| 用户配置 | `%APPDATA%/AgentMatrix/config.json` | 读写 |
| 导出文件 | `%APPDATA%/AgentMatrix/exports/` | 读写 |

**后端代码改造**：在 `app/main.py` 启动时检测 `sys._MEIPASS`（PyInstaller 环境）vs 普通 Python 运行，动态设置数据目录。若 `%APPDATA%/AgentMatrix/` 不存在则自动创建。

**依赖精简**：打包前使用 `pipdeptree` 扫描依赖树，移除未被 `import` 的包。锁定 `cryptography==3.4.8`（已知与 Python 3.9 兼容的版本）。

**Ollama 调用方式确认**：后端通过 `httpx.AsyncClient` 直接向 `http://localhost:11434/api/generate` 和 `http://localhost:11434/api/chat` 发送 HTTP POST 请求，**不依赖 `ollama` CLI 命令**。因此 PyInstaller 打包后无需处理 Ollama 可执行文件路径问题，只需确保 Ollama 服务在 11434 端口运行即可。此检查已纳入阶段 0.4 验证。

### 2.4 Ollama 环境检测与引导

```
EXE 启动
  ├── 1. 检测 Ollama 是否运行
  │     └── GET http://localhost:11434/api/tags (超时 3 秒)
  ├── 2. 若未运行 → 显示 ErrorOverlay 引导卡片
  │     ├── "检测到 Ollama 未运行，请先安装 Ollama"
  │     ├── [打开下载页] → https://ollama.com/download
  │     └── [重新检测]
  ├── 3. 若运行但无模型 → 显示模型下载引导
  │     ├── "需要下载模型: qwen2.5:1.5b, phi4-mini:3.8b"
  │     ├── [自动下载] → 调用 ollama pull，显示进度
  │     └── [跳过] → 仅云端模型可用（需 DeepSeek API Key）
  ├── 4. 若运行且模型就绪 → 启动后端
  └── 5. 后端启动后 → 显示主界面
```

### 2.5 WebView2 运行时处理

Tauri v2 依赖 WebView2（Windows 10 1809+ 预装，但早期版本/企业策略管控可能缺失）。

**安装器策略**：
- 安装器启动时检测 WebView2 是否存在
- 若不存在 → 静默触发 WebView2 Evergreen Bootstrapper
- 若安装成功 → 继续
- 若安装失败（权限不足/无网络）→ 弹出提示：`"AgentMatrix 需要 WebView2 运行时，请手动安装：https://go.microsoft.com/fwlink/p/?LinkId=2124703"`，退出安装

> **注意**：Tauri v2 仅支持 WebView2，不存在 IE/Edge 引擎回退路径。

## 四、错误边界与全局通知设计

### 4.1 ErrorOverlay 状态机

```
                    ┌──────────┐
         ┌─────────→│  空闲    │←─────────┐
         │ 手动关闭  │ (无通知)  │          │
         │          └────┬─────┘          │
         │               │ 错误事件        │
         │          ┌────▼─────┐          │
         │          │  通知栏   │ 自动消失  │
         │          │ (非阻塞)  │──────────┘
         │          └────┬─────┘
         │               │ 严重错误
         │          ┌────▼─────┐
         │          │  全屏遮罩 │ 手动重启
         │          │ (阻塞式)  │──────────┐
         │          └──────────┘          │
         └────────────────────────────────┘
```

**通知级别**：

| 级别 | 触发条件 | 展示方式 | 用户操作 |
|------|---------|----------|----------|
| 信息 | 云端模型降级通知 | 顶部通知栏，5秒自动消失 | 无 |
| 警告 | Ollama 未运行、API 超时 | 顶部通知栏，需手动关闭 | 关闭 / 查看详情 |
| 错误 | 后端崩溃、永久故障 | 全屏遮罩 + 手动重启按钮 | 手动重启后端 |

### 4.2 手动重启后端按钮

当 sidecar 进入"永久故障"状态（1 分钟内崩溃 5 次），前端显示全屏遮罩：

```
┌──────────────────────────────────────┐
│           ⚠ 后端服务异常              │
│                                      │
│  后端进程多次崩溃，可能原因：            │
│  - Ollama 服务异常                    │
│  - 端口被占用                         │
│  - 系统资源不足                        │
│                                      │
│  [尝试重新启动后端]  [查看日志]         │
│                                      │
│  详情: 最近 1 分钟内崩溃 5 次            │
└──────────────────────────────────────┘
```

点击"尝试重新启动后端"触发 `invoke('restart_sidecar')`（Tauri IPC 调用 Rust 命令），执行一次完整启动序列（含指数退避重试），重置计数器。

**重启后状态保留策略**：手动重启后端后，前端保留之前的用户输入和已完成的步骤日志，仅清空进行中的步骤状态。若重启后后端无法恢复之前的执行上下文，则显示"执行已中断，请重新提交"提示。

## 八、最终建议

### 不要做的事

1. **不要跳过阶段 0** — 静态导出和 PyInstaller 打包验证是前提，如果失败整个方案不可行
2. **不要跳过阶段 2 原型** — 用空 Tauri 先跑通 WebSocket + 重连 + 降级，这是最大的不确定因素
3. **不要同时拆分组件和 Tauri 集成** — 两个复杂任务叠加会双向阻塞
4. **不要低估 Rust 环境搭建** — Windows 上安装 Rust + VS Build Tools 可能需要半天

### 最小可行路径（如果时间极度紧张）

1. 跳过 Tauri，做 Next.js 静态导出 + `npx serve` 本地运行
2. 只做功能裁减（删除假数据、右键菜单），不做完整组件拆分
3. 用批处理脚本启动后端 + 前端
4. 2-3 天可得到一个"干净版"本地工具
