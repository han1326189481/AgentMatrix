# AgentMatrix 数据备份与回档机制

> 2026-10-04 建立。起因：2026-09-24 知识图谱（636 节点）被测试脚本的**空图全量覆盖**，
> 一度清零，靠一次偶然的整目录快照才救回来。**代码有 git 兜底，运行时数据没有。**

## 一、为什么要单独备份

git 管得住 `.py` / `.ts`，**管不住运行时被改写的文件**：

| 资产 | 位置 | 为什么 git 管不住 |
| --- | --- | --- |
| 知识图谱（636 节点） | `backend/core/graphs/skill_graph.yaml` | 运行时被自学习链路写入 |
| 推理图谱 | `backend/core/graphs/reasoning_graph.yaml` | 同上 |
| SQLite 主库 | `backend/storage/agentmatrix.db` | 被 `.gitignore` 排除 |
| 用户数据 | `backend/storage/{memory,profiles,pending_learning,workspace}` | 运行时状态 |
| 机密 | `backend/.env`、`backend/.token` | 被 `.gitignore` 排除 |

## 二、三层防线

| 层 | 触发时机 | 由谁执行 | 说明 |
| --- | --- | --- | --- |
| ① 启动快照 | 每次 `.\start_all.ps1` | 脚本内置 | 每次开工前留一份，零依赖 |
| ② 每日自动 | 每天 12:30 | WorkBuddy automation | 需 WorkBuddy 运行 |
| ③ 计划任务 | 每天（默认 21:30） | Windows 计划任务 | **脱离 WorkBuddy 独立运行**，需手动安装 |

三层互相独立，任一层生效即可保底。

## 三、日常操作

### 手动备份

```powershell
.\scripts\backup.ps1                      # 标签 auto
.\scripts\backup.ps1 -Label manual        # 自定义标签
.\scripts\backup.ps1 -Keep 60             # 保留 60 份（默认 30）
.\scripts\backup.ps1 -List                # 只看已有快照
```

**退出码**：`0` 成功 / `1` 失败 / `2` 被缩水拦截拒绝。

### 回档

```powershell
.\scripts\restore.ps1 -List                                   # 列出可用快照
.\scripts\restore.ps1                                         # 恢复最新一份（需输入 YES）
.\scripts\restore.ps1 -Snapshot 20260924                      # 按日期模糊匹配
.\scripts\restore.ps1 -Snapshot snapshot_20260924_210702_manual.zip
.\scripts\restore.ps1 -Yes                                    # 跳过确认（脚本化）
```

恢复前脚本会**自动把当前状态另存为 `prerevert` 快照**——所以即使恢复错了快照，还能再退回来。
恢复完成后建议重启后端，使其重新加载数据。

### 快照在哪

```
D:\AgentMatrix_backups\
├── snapshots\   snapshot_YYYYMMDD_HHMMSS_<label>.zip
├── logs\        backup-YYYY-MM.log
└── state.json   基线（上次成功的节点数，供缩水拦截比对）
```

⚠️ **该目录含 `.env` / `.token`，属于机密。不要放进云盘、不要提交到任何仓库。**

## 四、缩水拦截（最重要的一道闸）

`backup.ps1` 在打包前会调用 `scripts/graph_health.py` 读知识图谱节点数，并与
`state.json` 里的**上次成功基线**比对：

- 图谱读不出来（`health.ok = false`）→ **拒绝备份**，退出码 2
- 节点数 **< 基线的 50%** → **拒绝备份**，退出码 2

这条规则存在的唯一理由：**防止把已经损坏的状态当成"好状态"存下来，覆盖掉健康基线。**
9/24 事故时图谱只剩 2 节点，如果当时备份照跑，健康的 636 节点基线就没了。

**被拦截时不要习惯性加 `-Force`。** 先查清为什么缩水。确实要存异常现场时才用 `-Force`。

## 五、备份内容清单

```
backend/core/graphs/*.yaml                   知识图谱（最珍贵）
backend/storage/agentmatrix.db               SQLite 主库（sqlite3 backup API，含 WAL）
backend/storage/{memory,profiles,pending_learning,workspace}/
backend/config/app_config.json               运行时配置
backend/.env                                 含密钥
backend/.token                               含密钥
%APPDATA%\AgentMatrix\config\*               打包环境配置（存在才备份）
manifest.json                                快照元信息（时间/节点数/边数/主机）
```

**不备份**：`storage/sandboxes/`（临时沙盒）、`storage/backups/`（是备份本身）、
整个仓库代码（交给 git）。

### 为什么 SQLite 要用 `db_backup.py` 而不是直接拷贝

运行时 SQLite 处于 **WAL 模式**，未 checkpoint 的数据只存在于 `-wal` 文件里。
直接 `Copy-Item agentmatrix.db` 会得到残缺快照 —— 实测差 **90%**（16KB vs 167KB）。

`scripts/db_backup.py` 走 `sqlite3` 的 backup API，在事务一致性点上拷贝，
自动包含 WAL，不停服、不阻塞写入，并对结果跑 `PRAGMA integrity_check` 自检。

## 六、安装每日计划任务（可选但推荐）

```powershell
# 以【管理员身份】运行 PowerShell
.\scripts\install_backup_task.ps1                 # 每天 21:30
.\scripts\install_backup_task.ps1 -Time 09:00     # 自定义
.\scripts\install_backup_task.ps1 -Uninstall      # 卸载
```

任务名 `AgentMatrix-DailyBackup`，以当前用户身份、仅在登录时运行（不存密码）。

## 七、已知红线

1. **测试不得写生产数据。** `backend/tests/conftest.py` 已用 5 个 autouse fixture
   封住 LearningEngine / KnowledgeAuditor / ReasoningGraph / PendingStore / 用户画像
   的写入通道。新增需要落盘的测试必须显式传 `tmp_path`。
2. **`LearningEngine` / `KnowledgeAuditor` 的缩水护栏不可移除。**
   （`MIN_NODE_RETENTION = 0.5`，内存图 < 磁盘一半即拒绝写入。）
3. **备份目录是机密的。** 含 `.env` 与 `.token`。
